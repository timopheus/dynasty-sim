# Решения

Принятое решение не меняется молча. Нужно другое — новая запись со ссылкой на старую и причиной, а у старой статус «заменено D-NNN».

Формат: **D-NNN. Название** — дата, статус; контекст, решение, последствия.

---

## D-001. Стек
2026-10-15 · принято

**Контекст.** Игра текстовая, в браузере. Тим принимает работу по хронике, поэтому симуляция должна запускаться без интерфейса.

**Решение.**
- TypeScript (strict), игра в браузере на Vite. Node 22 для инструментов.
- Ядро `src/core` отдельно от интерфейса `src/ui`: свой tsconfig без DOM и Node, правила проверяет тест архитектуры.
- Тесты — Vitest. Скрипты в `tools/` запускаются через tsx.
- Схема контента — zod 4, парсер YAML — `yaml` (YAML 1.2).
- Интерфейс пока без фреймворка, обычный DOM. Вопрос фреймворка — к задаче 2.8.
- Версии зависимостей закреплены точно. TypeScript 7 используется только для проверки типов (`tsc --noEmit`). Если он помешает инструментам, откат на 6.0 без других изменений.
- Сохранения — JSON.

**Последствия.** Ядро можно гонять в Node (прогоны, тесты) и в браузере одним и тем же кодом. Любая зависимость ядра от браузера или диска — ошибка сборки.

## D-002. Контент как данные
2026-10-15 · принято

**Контекст.** Игра держится на большом количестве событий и действий. Их должны писать агенты и Тим без программирования.

**Решение.**
- Контент лежит в `content/` в YAML. Каждый файл — объект с ключами `settings`, `names`, `actions`, `events`; файлы сливаются в алфавитном порядке пути.
- Схема — `src/core/content/schema.ts`: неизвестные поля запрещены, числа целые, id в `lower_snake_case`.
- Загрузчик проверяет перекрёстные ссылки, уникальность id и плейсхолдеры в текстах. Ошибка указывает файл и путь до поля.
- Ядро получает тексты файлов, а не читает диск. Node-инструменты читают `content/` с диска, браузер подключает те же файлы при сборке.
- Все тексты игры, включая системные (смерть, наследование), — в контенте, не в коде.

**Последствия.** `npm run validate` — обязательная проверка в CI. Новое поле контента добавляется в три места: схема, загрузчик, плохой пример в тестах.

## D-003. Seed и детерминизм
2026-10-15 · принято

**Контекст.** Историю нужно воспроизводить: для отладки, баланса и разговора о конкретном прогоне.

**Решение.**
- Вся случайность ядра — через генератор sfc32 (`src/core/rng.ts`), seed разворачивается через splitmix32. Seed — целое от 0 до 4294967295.
- Состояние генератора хранится в `GameState` и сохраняется вместе с игрой, поэтому загрузка продолжает ту же историю.
- В ядре запрещены `Math.random`, `Date`, `performance` и трансцендентные функции `Math` (`exp`, `pow`, `log`, `sin`…), так как их результат может отличаться между движками. Вероятности — целые дроби (`chancePer(r, n, d)`), таблицы — целые числа.
- Состояние — чистый JSON: без классов, `Map`, `undefined`.
- Бот для прогонов использует свой поток (`seedRng(seed, 1)`) и не сдвигает мировой. Функции-запросы случайность не тратят.

**Последствия.** Одинаковый seed и одинаковый контент дают одинаковую хронику байт в байт; это проверяют тесты. Любое изменение контента меняет хроники, поэтому «золотых» снимков нет.

## D-004. Роли моделей
2026-10-15 · принято

**Контекст.** Работа идёт отдельными облачными сессиями и субагентами. Нужен баланс качества и стоимости.

**Решение.** Сессии по умолчанию на Sonnet 5.5, effort medium. Субагенты в `.claude/agents/`:

| Агент | Модель | Effort | Назначение |
|---|---|---|---|
| architect | opus | high | план этапа, архитектура, сложные баги |
| implementer | sonnet | medium | код по готовому плану |
| content-writer | sonnet | medium | события пачками по схеме |
| scout | haiku | low | поиск, обновление доков, прогоны со сводкой |
| reviewer | opus | high | независимая проверка перед мержем; только чтение и проверки |

Сессия с архитектурной задачей — на Opus. Fable — только по прямой просьбе Тима.

**Последствия.** Модель и effort заданы во frontmatter агентов. Reviewer не может править файлы (`disallowedTools: Write, Edit`). Ограничение его Bash командами проверок задано инструкцией, а не настройкой: Claude Code не поддерживает такие шаблоны в `tools`.

## D-005. Язык
2026-10-15 · принято

**Решение.** С Тимом, в docs, в описаниях PR, в CLAUDE.md и инструкциях агентов — по-русски. Код, комментарии, имена, сообщения коммитов и тексты игры — на английском.

**Последствия.** Хроника (текст игры) — на английском, сводки по ней для Тима — по-русски.

## D-006. Календарь
2026-10-15 · принято

**Решение.** Время — целый номер дня; день 0 — 1 января 1700 года. Календарь григорианский: 1700 и 1800 годы не високосные. Даты до 1700 года отрицательные (на них приходятся даты рождения). Шаг симуляции — один день.

**Последствия.** Возраст считается по датам, а не делением на 365. Если понадобится юлианский календарь для отдельных держав, это будет отображение поверх номера дня.

## D-007. Временный наследник до этапа 4
2026-10-15 · принято (решение Тима)

**Контекст.** В каркасе один персонаж, а прогон рассчитан на 300 лет.

**Решение.** Когда глава рода умирает, появляется сгенерированный взрослый наследник (возраст из `settings.heirAge`, та же фамилия). Ему переходят деньги, больше ничего. Текущее действие прерывается.

**Последствия.** Прогоны идут все 300 лет и проверяют календарь, смертность и скорость. Заглушку заменит этап 4 «Династия».

## D-008. Координация через репозиторий
2026-10-15 · принято

**Контекст.** Каждый тред — отдельная облачная сессия Claude Code без общего проекта и общей памяти.

**Решение.**
- Общая память — только репозиторий: CLAUDE.md, `.claude/rules/workflow.md` (загружается в каждую сессию), docs/.
- Задача занята, если по её ID есть открытый PR `[ID] …`.
- Ведущая сессия запускает задачи утверждённого плана новыми облачными сессиями: не больше 3 одновременно, только из разных модулей, с самодостаточным промптом. Дочерние сессии новых не запускают.
- Сессия, открывшая PR, сама доводит его до мержа.

**Последствия.** Всё, что нужно следующей сессии, должно попасть в docs до мержа. Параллельные PR могут конфликтовать в STATUS и CHANGELOG: перед мержем вливается свежий main.

## D-009. Масштаб карты
2026-10-15 · принято (решение Тима)

**Решение.** Карта — средний регион с морем: 40–60 провинций, 15–25 городов, побережье и внутреннее море. Этого хватает морской торговой державе и султанской с её портами, а вручную такую карту ещё можно проработать.

**Последствия.** Задача 1.6 выбирает в Azgaar регион этого размера. Конкретный регион и формат импорта решаются там же.

## D-010. Пол персонажей, браки и дети
2026-10-15 · принято (решение Тима)

**Решение.** Пол персонажей появляется на этапе 2, в задаче 2.3. Браки, дети и правила наследования — на этапе 4, вместе с династией.

**Последствия.** После 2.3 тексты могут использовать местоимения, а запрет «без местоимений» снимается в той же задаче — в CLAUDE.md и в `.claude/agents/content-writer.md`. До этапа 4 наследник остаётся временным (D-007).

## D-011. Состав CI
2026-10-15 · принято (решение Тима)

**Решение.** CI на каждый PR и push в main: проверка типов, тесты, валидатор контента, прогон на 50 лет (seed 1), сборка. Хроника прогона прикладывается к результату.

**Последствия.** Менять состав CI — только с согласия Тима (см. `.claude/rules/workflow.md`).

## D-012. Формат вопросов Тиму
2026-10-15 · принято (решение Тима)

**Решение.** Вопросы Тиму задаются инструментом вопросов: 2–4 варианта, первый рекомендуемый с пометкой «(Recommended)», у каждого одна строка о последствиях. Несрочные вопросы записываются в STATUS в том же виде.

**Последствия.** Правило записано в `.claude/rules/workflow.md` (Координация, п. 9) и действует во всех сессиях.

## D-013. Опоры игры
2026-10-15 · принято (решение Тима, задача 1.2)

**Контекст.** В GDD v0.1 опоры смешивали ощущения игрока и технические условия (данные в YAML, seed). По техническим пунктам нельзя решать спорные вопросы дизайна.

**Решение.** Пять опор игры (GDD §2): история из системы, не из сценария; хрупкий взлёт; последствия живут дольше героя; мир живёт без игрока; хроника — главный результат. «Данные, а не код» и «воспроизводимость» вынесены в подраздел «Принципы разработки»; они по-прежнему действуют (D-002, D-003).

**Последствия.** Спорная идея проверяется по опорам: противоречит опоре — меняется идея. Новая опора или правка старой — новой записью в DECISIONS.

## D-014. Темп игры
2026-10-15 · принято (решение Тима, задача 1.2)

**Решение.** Решение игрока — раз в 1–2 минуты игры. Действия длятся от недель до месяцев, за действие 2–4 события с выбором. За 10 минут проходит 1–3 года жизни героя.

**Последствия.** Это ориентир для длительностей действий, частоты событий и рассказчика (этапы 2–3) и для метрик прогона (2.7): среднее число событий с выбором на год жизни.

## D-015. Амбиции главы рода и слава рода
2026-10-15 · принято (решение Тима, задача 1.2)

**Контекст.** Победы нет (D-016), но игроку нужна цель на жизнь героя и причина играть за следующее поколение.

**Решение.**
- Игра предлагает 2–3 амбиции по текущему положению героя (роль, долги, враги, покровители). Игрок выбирает одну и может сменить. Амбиции — контент, роль добавляет свои (у авантюриста — «осесть»).
- Слава рода копится поколениями из подвигов и позора глав и влияет на доступ к дворам, покровителям, бракам. Это сверх наследства, которое реально остаётся в мире.

**Последствия.** Нужны системы амбиций и славы рода; этап и формат определит architect при планировании этапов 3–4 и 6. Достигнутые и проваленные амбиции попадают в хронику.

## D-016. Конец игры и сохранения
2026-10-15 · принято (решение Тима, задача 1.2)

**Решение.**
- Победы и оценки нет. Партия кончается, когда род пресёкся (наследника нет) или игрок сам её завершил. Предела по времени нет.
- В игре одно автосохранение, без ручных сохранений и откатов: решения и случайности окончательны.
- В конце игрок видит полную хронику и итог рода: годы и поколения, главы рода, достигнутые и проваленные амбиции, слава, вершина и дно рода.

**Последствия.** Сохранение и загрузка из файла и по seed (D-003) остаются инструментом разработки и прогонов, игроку они не показываются. В задаче 2.8 интерфейс делает автосохранение после каждой команды игрока, включая выбор в событии, а не кнопки «сохранить/загрузить»: иначе перезагрузка страницы даст переиграть выбор. Временный наследник (D-007) пока не даёт роду пресечься; пресечение появится на этапе 4.

## D-017. Падение не кончает игру
2026-10-15 · принято (решение Тима, задача 1.2)

**Решение.** Разорение, тюрьма, опала, увечье — не конец партии, а новое положение героя со своими действиями и событиями (бегство, долговая тюрьма, служба за гроши), из которого можно выбраться. Партию кончает только пресечение рода или выход игрока (D-016).

**Последствия.** Контент должен покрывать «дно»: у положений падения есть доступные действия и пути наверх. Состояние героя без доступных действий — ошибка, которую стоит ловить инвариантом, когда появятся условия доступности (2.2).

## D-018. Игрок готовит наследника заранее
2026-10-15 · принято (решение Тима, задача 1.2)

**Решение.** Наследник виден игроку при жизни героя. Воспитание, брак, завещание влияют на следующую жизнь.

**Последствия.** Полностью — на этапе 4 вместе с браками и детьми (D-010). До того действует временный наследник (D-007).
