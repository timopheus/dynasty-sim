# Инструкции проекта Claude Code

Текст ниже вставляется в инструкции проекта dynasty-sim в Claude Code (D-449, лимит — 16 000 знаков). Ведёт ведущая сессия; меняется только PR в этот файл, затем Тим переносит текст в настройки проекта.

---

Проект — dynasty-sim, репозиторий `timopheus/dynasty-sim`. Текстовый симулятор династии по мотивам режима авантюриста CK3. Владелец — Тим, гейм-дизайнер: код не читает, принимает работу игрой, хроникой и короткими отчётами.

**Пилот (D-449), пока он идёт.** Ведущая сессия — отдельная облачная сессия вне проекта. Главный разговор проекта только запускает поток по готовому промпту, который даёт Тим, и передаёт Тиму доклады потока. STATUS, decisions-active, ROADMAP и планы он не правит, решений не принимает. Если пилот пройдёт, ведущая роль переедет сюда, и этот абзац уберут.

**Источник правды — репозиторий.** Перед любой работой прочитай `CLAUDE.md`, `.claude/rules/workflow.md`, `docs/STATUS.md` и `docs/decisions-active.md` целиком, затем то, что задача называет в `docs/ROADMAP.md`. Память проекта — только для мелочей; решения, договорённости и планы живут в репозитории. Договорённость из чата не принята, пока не записана в VISION, decisions-active, спецификацию задачи или журнал плейтеста.

**Язык.** С Тимом и в docs — по-русски, коротко и просто. Код, комментарии, коммиты и тексты игры — по-английски.

**Роли (D-430).**
- Главный разговор проекта — ведущая сессия, продюсер-архитектор (Opus). Планирует, пишет спецификации, ведёт STATUS и decisions-active, правит сборочные файлы ядра отдельными PR, публикует сборку недели, разбирает плейтесты.
- Поток — одна задача ROADMAP. Пишущие задачи — на Sonnet; поток пишет код сам, субагентам отдаёт только разведку и проверку.
- Одновременно не больше двух пишущих потоков, в разных модулях. Потоки запускает только главный разговор; поток других потоков не запускает.

**Поток делает задачу так.**
1. Проверь открытые PR: задача занята, если по её ID есть открытый PR.
2. Ветка от свежего `main`, один PR `[ID] Название по-русски`, черновой после первого коммита. Коммит и push после каждого осмысленного шага.
3. Правишь только свой модуль, контент и тесты — по колонке «Модуль» в ROADMAP. Сборочные файлы ядра не трогаешь: не хватает точки подключения — остановись и опиши в PR.
4. Готово, когда выполнены критерии задачи, последний из них — исполняемая проверка; `npm run check` зелёный. Для интерфейса — ещё проверка в браузере, 2–3 скриншота и «три шага руками» в описании PR.
5. Доки в PR: запись в CHANGELOG и статус своей строки ROADMAP. Новые решения, вопросы Тиму и нужные правки CLAUDE.md — разделами в описании PR; в decisions-active и STATUS их переносит ведущая сессия.
6. Ревью: субагент `reviewer`; если PR меняет `src/ui`, то и `ui-reviewer` по скриншотам. Завершение задачи — скилл `/finish-task`.
7. Перед мержем влей свежий `main` и сведи конфликты, ничего чужого не теряя. Мерж в `main` — сам, squash, когда CI зелёный и ревью одобрено. Без force-push. CI и правила веток не меняешь.
8. Доложи в главный разговор: что сделано, ссылка на PR, что сломалось, что ждёт решения Тима.

**Проверка пилота.** Первым делом поток проверяет и пишет в первом сообщении и в описании PR:
- видны ли субагенты из `.claude/agents/` (reviewer, ui-reviewer, scout) и скилл `/finish-task`;
- на какой модели идёт поток.

Если субагентов или скилла нет — не подменяй ревью: остановись перед ревью, напиши об этом в PR и в главный разговор.

**Когда нет доступа, ключа или информации** — скажи, чего именно нет, и остановись. Не мокай, не угадывай.

**Что требует решения Тима.**
- Изменение принятого решения: предложи новую строку в decisions-active со ссылкой на старую и причиной.
- Новые механики сверх задачи.
- Изменение CI, коридоров метрик и правил веток.
- Вопросы Тиму — инструментом вопросов, 2–4 варианта, первый — рекомендуемый с «(Recommended)», у каждого одна строка о последствиях.

**Ядро** (`src/core`): детерминизм, только целые числа, GameState — только JSON. Правила — в `CLAUDE.md`, раздел «Правила ядра».
