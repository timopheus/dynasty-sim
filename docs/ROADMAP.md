# Дорожная карта

Статусы: ⬜ не начата · 🟡 в работе · ✅ готово. Задача занята, если по её ID есть открытый PR `[ID] …`.
Этап начинается с плана от architect и «ок» Тима (см. `.claude/rules/workflow.md`). Разбивка этапа 2 предварительная: architect уточнит её в начале этапа.

## Этап 2. Скелет симуляции
Цель: ядро, на котором держатся все следующие этапы. Герой и люди вокруг живут, стареют, умирают и связаны отношениями. Всё сохраняется и воспроизводится по seed. Хроника читается.

| ID | Задача | Модуль | Зависит от | Готово, когда |
|---|---|---|---|---|
| 2.1 | Состояние и сохранения | `src/core/game.ts`, `src/core/save/` | — | Версионированный формат JSON, миграции, проверка схемы сохранения; сохранение и загрузка посреди события дают тот же прогон |
| 2.2 | Время и действия как данные | `src/core/time/`, `content/actions` | 2.1 | Условия доступности действий, прерывания, отложенные эффекты (планировщик); тесты на порядок дня |
| 2.3 | Персонаж: характеристики, черты, здоровье, пол | `src/core/character/`, `content/traits` | 2.1, 1.4 | По GDD §8: шесть характеристик (D-031); черты как данные с категориями и противоположностями, образование с уровнями (D-032); состояния здоровья со стадиями вместо шкалы 0–100, смертность по таблице и состояниям, причина смерти (D-033); пол как поле персонажа с запросом для условий и местоимения в шаблонах (D-010, D-034; сами условия по полу — в 2.2 и на этапе 3); известность и заметность черт (D-037); прогон показывает правдоподобную продолжительность жизни |
| 2.4 | Мнения и отношения | `src/core/relations/` | 2.1, 1.4 | По GDD §8: причины мнения с правилами затухания и влиянием черт, наследуемые причины (D-035); отношения друг, соперник, покровитель ↔ протеже, любовник (D-036); знакомство героя и тайны со списком знающих (D-037); инварианты связей |
| 2.5 | Население вокруг героя | `src/core/world/` | 2.3 | Генерация персонажей рядом с героем, грубый годовой тик для дальних; прогон на 300 лет укладывается в разумное время |
| 2.6 | Хроника v1 | `src/core/chronicle/` | 2.1 | Структурированные записи (кто, что, где), биография главы рода и история мира, экспорт в markdown |
| 2.7 | Метрики прогона | `tools/`, `src/core/sim.ts` | 2.3 | `npm run sim` выводит статистику (продолжительность жизни, частоты событий, деньги) и сравнивает два прогона |
| 2.8 | Текстовый интерфейс v1 | `src/ui/` | 2.1, 2.2 | Экран героя, список действий с условиями, журнал, автосохранение в браузере после каждой команды (D-016) |

После 2.1 параллельно можно вести 2.2, 2.3 (после 1.4) и 2.6: модули разные.

## Этап 3. Движок событий
Storylets по формату из 1.5: условия, вес, роли из живущих персонажей, шаблоны с грамматикой, варианты, последствия, продолжения. Рассказчик управляет темпом. Предыстория первого героя — цепочка сцен на этом движке (D-038).

## Этап 4. Династия
Браки и дети (D-010), смерть, наследник по правилам, наследство: деньги, долги, репутация, враги, обещания. Временный наследник из каркаса (D-007) заменяется настоящим. Игрок готовит наследника заранее (D-018); слава рода (D-015); пресечение рода, выход игрока и итог рода в конце партии (D-016).

## Этап 5. Мир
Карта из Azgaar как данные, державы-прототипы, грубая симуляция вдали и подробная рядом, история мира в хронике.

## Этап 6. Роль авантюриста
Сцены предыстории авантюриста (D-038); отряд, контракты, покровители, рекомендательные письма, векселя; амбиции главы рода, у авантюриста главная — осесть (D-015); положения падения с путями наверх (D-017). Первая роль как пакет поверх ядра.

## Этап 7. Контент-конвейер
Пакетное написание событий агентом content-writer, проверки однообразия и баланса по прогонам, инструменты для Тима.

## Этап 8. Новые роли пакетами
Купец, офицер, дворянин — каждая роль отдельным пакетом без изменений ядра.
