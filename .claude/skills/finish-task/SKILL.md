# Завершение задачи $ARGUMENTS

Иди по шагам. Шаг не прошёл — исправь и повтори, не перескакивай.

## 1. Проверки
```
npm run typecheck
npm test
npm run validate
npm run sim -- --years 300 --seed 1
npm run sim -- --years 300 --seed 2
npm run build
```
Все без ошибок, в прогонах «Invariant violations: none».

## 2. Доки
- `docs/CHANGELOG.md`: запись сверху с датой, ID и что изменилось для игры и проекта.
- `docs/STATUS.md`: что теперь работает, какие заглушки остались, что дальше, вопросы к Тиму.
- `docs/ROADMAP.md`: статус задачи — «готово» (со ссылкой на PR).
- `docs/DECISIONS.md`: новые решения отдельными записями. Изменение принятого решения — только новой записью со ссылкой на старую.
- `CLAUDE.md`: если поменялись команды, структура или правила.

## 3. Коммит и PR
- Коммит на английском, push в ветку задачи.
- Если PR ещё нет — создай черновой. Заголовок `[ID] Название по-русски`. Описание по-русски:
  - **Что сделано** — для Тима, языком игры, без пересказа шагов;
  - **Как проверить** — команды и что увидеть (например, seed и строки хроники);
  - **Решения** — ссылки на новые записи DECISIONS;
  - **Что осталось** — заглушки и следующие задачи.
- Перед мержем влей свежий `origin/main` в ветку (merge, не rebase), если он ушёл вперёд, и сведи конфликты в доках, ничего чужого не теряя.

## 4. Review
Запусти субагента `reviewer` (инструмент Agent, `subagent_type: reviewer`). Передай: ID задачи, ветку, номер PR, одну-две фразы о цели задачи. Не пересказывай, как писался код.
- «НУЖНЫ ПРАВКИ» — исправь, закоммить, запусти reviewer заново.
- Замечания «(необязательно)» — исправь, если это дёшево и в рамках задачи; иначе перечисли в описании PR.

## 5. CI
Подпишись на события PR и закончи ход: CI сам разбудит сессию. Не жди в цикле и не опрашивай статус через `sleep`. Упал CI — найди причину в логах, исправь, push, снова жди.

## 6. Мерж
Когда CI зелёный и reviewer одобрил:
1. Выведи PR из черновика.
2. Squash-мерж в main, заголовок коммита — заголовок PR с номером.
3. Без force-push, без правок CI и правил веток.

## 7. Отчёт Тиму
Три коротких блока: что сделано, что сломалось (если было), что ждёт его решения. Ссылка на PR.
